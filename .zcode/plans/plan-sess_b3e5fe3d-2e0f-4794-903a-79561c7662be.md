## 目标
将前端 UI 从 HeroUI v3 完整迁移到 shadcn/ui 风格的本地组件，保留现有认证、服务状态、D1 读写和请求链路行为；Worker、Hono、D1、Drizzle API 不改。

## 实施步骤
1. **建立 shadcn/ui 基础配置**
   - 在 `package.json` 中移除 `@heroui/react` 及仅由 HeroUI 使用的 React Aria/React Spectrum 直接依赖；保留 React、Tailwind v4、Lucide 和业务依赖。
   - 增加 shadcn 组件所需的直接依赖（Radix primitives、`class-variance-authority`、`clsx`、`tailwind-merge`，按实际组件需要精确添加），更新 `package-lock.json`。
   - 增加 `components.json`，采用 Tailwind CSS v4/Vite 兼容配置；在 `tsconfig.json` 和 `vite.config.ts` 增加一致的 `@/*` 到 `src/*` 别名，避免 TypeScript 与 Vite 解析不一致。
   - 在 `src/client/lib/utils.ts` 提供标准 `cn` 辅助函数，并将组件放在 `src/client/components/ui/`，与当前前端目录边界一致。

2. **添加所需的本地 shadcn 组件**
   - 创建/引入并按项目 Tailwind v4 语法调整 `button`、`card`、`badge`、`alert`、`input`、`label`、`progress`、`table`、`spinner`（或使用 LoaderCircle 图标实现加载状态）组件。
   - 对 shadcn 默认组件做最小的主题适配：支持 primary/secondary/outline/ghost、成功/警告/危险状态、禁用态、焦点态、键盘可操作性和正确的 ARIA 属性。
   - 为 TOTP 登录实现 shadcn 组件组合（`InputOTP`/`InputOTPGroup`/`InputOTPSlot`，以及数字 pattern、6 位长度、错误和禁用状态），不改变现有受控值和提交逻辑。

3. **重写 `src/client/App.tsx` 的 UI 层**
   - 将 HeroUI 的 import 和 compound API 全部替换为本地 shadcn 组件及原生语义结构；把 `onPress` 改为标准 React `onClick`，将 `isDisabled`/`isInvalid`/`fullWidth` 等属性映射为 `disabled`、状态 class 和布局 class。
   - 保留现有 fetch、状态机、认证流程、loading/error/saved 状态和所有文案；不修改 API 路径、请求方法或数据类型。
   - 保留 Lucide 图标，并给图标按钮维持 `aria-label`；确保表格表头/行头、进度条、错误提示和 OTP 输入的可访问性。
   - 顺手修正服务数量显示在真实空列表时回退为 3 的现有 UI 问题，改为准确显示 `services.length`，并为空服务列表增加清晰的空状态行，避免迁移后出现空白表格。
   - 更新请求链路和技术栈文案中的 `HeroUI` 为 `shadcn/ui`，使界面与实际技术栈一致。

4. **迁移全局样式与主题 token**
   - 删除 `@import "@heroui/styles"`，保留 `@import "tailwindcss"` 为第一条导入。
   - 在 `src/client/styles.css` 建立 shadcn 常用的 light/dark-compatible CSS variables（background/foreground/card/border/input/primary/secondary/muted/accent/destructive/ring 等），并将现有 HeroUI 专属 token（`surface-secondary`、`separator`、success/danger token）映射到这些变量或项目自有语义变量。
   - 保留现有页面布局和响应式断点，改写依赖 HeroUI 生成类名的选择器（如 `.card__title`、`.card__content`）为本地组件 class/语义结构；确保桌面、窄屏和 380px OTP 视图无溢出或重排异常。

5. **清理构建配置并验证**
   - 删除 `vite.config.ts` 中只服务于 HeroUI/React Aria 的 `heroui-vendor` 分包规则；如有必要，将新 Radix/shadcn 依赖纳入合理 vendor 分组，但不引入新的框架。
   - 执行 `npm ci`、`npm run build`、`npm test`、`npm run check`，修复类型、构建或 Worker 回归问题。
   - 启动 Vite 开发服务器，使用浏览器检查登录页、认证失败/成功、仪表盘加载、数据库读写、退出登录，以及桌面和移动端尺寸；确认 API 行为和视觉布局均正常。

## 交付结果
完成后代码库不再依赖 HeroUI，UI 组件统一由 `src/client/components/ui/` 中的 shadcn 风格本地组件提供，保留原有 Cloudflare 全栈结构和业务行为，并报告验证命令与浏览器检查结果。
